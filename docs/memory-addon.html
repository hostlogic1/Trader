OpenClaw Memory Add-on — Implementation Report

Source project: mdkrush/openclaw-jarvis-memory • Generated: 2026-02-20
Quick takeaway

This repo is a blueprint + scripts for adding persistent memory to OpenClaw using a 3-layer approach: (1) Redis buffer for captured turns, (2) optional daily markdown logs, and (3) Qdrant vector DB for long-term semantic memory using Ollama embeddings. It can work on our VPS, but needs path/config updates (workspace is /data/.openclaw/workspace, not ~/.openclaw/workspace) and security hardening (bind services to localhost; consider PII retention/redaction).

1) What the project does / how memory is implemented

  • Layer 1 — Redis short-term buffer: captures OpenClaw session JSONL turns into Redis list keys (e.g., mem:<user_id>). New in v1.5.0: token-free capture reads JSONL files directly and tracks byte offsets.
  • Layer 2 — Daily .md logs: conceptually uses workspace/memory/YYYY-MM-DD.md as a human audit trail. Some scripts exist but parts are not portable as-written.
  • Layer 3 — Qdrant long-term memory: stores semantic vectors in Qdrant collection (default kimi_memories) using Ollama embeddings (default model snowflake-arctic-embed2).

2) Compatibility with our OpenClaw setup

  • Core approach works if scripts point to our real paths (sessions + workspace) and services are reachable.
  • We must override defaults to use /data/.openclaw/workspace and the correct sessions dir under /data/.openclaw/agents/....
  • Some scripts are hardcoded to /root paths and LAN IPs; those should not be run unchanged.

3) Step-by-step implementation plan (safe / explicit)

Phase A — Decide deployment model

  • Run Redis + Qdrant + Ollama via Docker on the VPS host (recommended).
  • Use token-free capture (cron_capture.py every N minutes) + daily backup (cron_backup.py).

Phase B — Bring up services

  • Use a docker-compose with ports bound to localhost only (security): 127.0.0.1:6379, 127.0.0.1:6333, 127.0.0.1:11434.
  • Persist volumes for Redis/Qdrant/Ollama.

Phase C — Configure env paths

Create a config file (example):

OPENCLAW_WORKSPACE=/data/.openclaw/workspace
OPENCLAW_SESSIONS_DIR=/data/.openclaw/agents/main/sessions
REDIS_HOST=127.0.0.1
REDIS_PORT=6379
QDRANT_URL=http://127.0.0.1:6333
OLLAMA_URL=http://127.0.0.1:11434/v1
USER_ID=<your persistent user id>

Phase D — Enable automation

  • Every 5 minutes: run token-free capture to append new turns to Redis.
  • Daily at 03:00: flush Redis turns into Qdrant (dedup via content hash).

4) Security / privacy notes

  • PII retention: you are storing conversation text; consider redaction and retention policies.
  • No auth by default: Redis/Qdrant are unauthenticated; bind to localhost and protect with firewall; optionally add auth/TLS.
  • Backups/logs may contain sensitive info; protect permissions and avoid public storage.
